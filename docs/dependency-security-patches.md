# Dependency security fixes

Run `node --test scripts/security-dependency-smoke.mjs` after a frozen pnpm
install. It exercises the actual packages resolved through the web and mobile
consumers, including malicious inputs and ordinary behavior.

| Package       | Advisory            | Resolution                                                                   |
| ------------- | ------------------- | ---------------------------------------------------------------------------- |
| proxy-addr    | GHSA-jqcg-44mw-7w3h | Override to patched 2.0.8                                                    |
| source-map-js | GHSA-68fv-2mgg-jv7q | Override to patched 1.2.2                                                    |
| compression   | GHSA-vc2v-76pw-4v95 | Override to patched 1.8.2                                                    |
| node-forge    | GHSA-86w9-cpqp-85rv | Patch 1.4.0: enforce nested DigestAlgorithm element count                    |
| braces        | GHSA-vfj7-8cjw-p6xm | Patch 3.0.3: bound parser and recursive AST walker nesting                   |
| elliptic      | GHSA-848j-6mx2-7j84 | Patch 6.6.1: preserve generated nonce octet width during RFC 6979 truncation |
| sprintf-js    | GHSA-hp3w-g68c-fv3c | Upgrade to latest 1.1.3 and patch numeric precision bounds                   |

As of 2026-10-06, the last four packages have no patched npm release. The
checked-in pnpm patches are applied reproducibly by the lockfile, without
changing package versions, hiding advisories, or bypassing the package firewall.
Version-only scanners will therefore still report these four advisories.
Use pnpm for installs: the legacy npm override block cannot apply pnpm patches.

The node-forge patch follows the element-count check proposed in
[upstream pull request 1152](https://github.com/digitalbazaar/forge/pull/1152).
The elliptic patch preserves the full generated byte width before converting
the nonce to an integer, including leading zero bytes; it leaves explicit custom
`options.k` callbacks unchanged.
Braces rejects nesting at 128 levels with a deliberate `SyntaxError` instead of
uncontrolled stack exhaustion, including directly supplied ASTs.
Sprintf clamps numeric precision to the ECMAScript limits (0–100 for `e`/`f`,
1–100 for `g`), so malicious precision cannot trigger a native `RangeError`.

Replace each local patch with an upstream fixed release when available, and keep
the regression checks. Do not treat a version-only finding as evidence that the
installed package patch was skipped; verify its behavior and lockfile patch hash.
